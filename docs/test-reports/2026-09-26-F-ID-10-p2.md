## 1. Scope

**What this Part is.** `/app/home` is now the real class-by-class basic-mode
home instead of Part 1's placeholder: a today strip (greeting, date, "N roll
calls not taken" or "Nothing waiting"), one big `ClassBlock` per class the
teacher is assigned to (class teacher, subject teacher, or both — F-AC-01
Part 5's `listMySections`), an "All classes" block for owner/admin, and an
essentials row. Every basic screen now sits inside `BasicShell` (Home +
brand + Help, no sidebar/bottom nav), applied to the whole `/app` shell in
basic mode, not only `/app/home` (D-405 item 5). Tapping a class opens the
existing (not yet basic-sized) roll call — the class hub is Part 3 (D-405
item 4). Also fixed: `#64`'s review-flagged `signInWithPassword` gap (a
`fetchUiPreferences` failure now deletes both `ui_mode`/`text_size` cookies
instead of leaving a stale one).

**Review batch (PR #72, same-day update — D-405 addendum has full detail).**
The persona this Part serves is an older teacher on a 360px phone, possibly
reading Extra large বাংলা text, who must never get stuck. This batch: moved
Sign out and a language switch into the essentials row (basic mode has no
`UserMenu` at all, which was the only other place either control lived) and
dropped Profile (`/account/security`, a layout-less dead end) instead of
building it a shell; replaced `HelpSheet`'s 16px English-only "✕" with a
full-width "ফিরে যান / Go back" button; fixed a real overflow found by this
batch's own manual screenshot pass (the phone Call button's text clipped
past its own edge at 360px + Extra large — now wraps); removed
`(school)/app/layout.tsx`'s `getSchoolProfile` request waterfall with a
`React.cache()`-wrapped loader; localised the home error state with a Retry
link; added a marks-entry line to the Help catalogue; and moved
`buttonVariants` into a radix-free `packages/ui/src/components/button-variants.ts`
so `essentials-row.tsx`/`home/page.tsx` compute real button classes instead
of a literal-string copy that had already drifted from them.

**Built on a dependency that landed mid-PR.** `section_subjects` (F-AC-01
Part 5, PR #73) was still open when this Part started, so it was built
first against a named interim assignment source, behind one function, for
exactly this reason. #73 merged (D-107, `listMySections` — built and named
specifically for this loader) before this PR was marked ready, so the
interim was swapped out before shipping; nothing interim remains (D-405).

### Notable cases proven

- A section where the caller is only class teacher, only a subject teacher,
  or both, produces exactly **one** `ClassBlock` — `listMySections`'s own
  grouping is trusted, not re-derived by `buildClassBlocks`.
- `taken`/`expected` are read from the saved session, not the live enrolled
  count, so they can legitimately differ — the "reports taken/expected from
  the saved session" test.
- A non-school day marks every block `not_school_day` even when a session
  exists (an `allow_non_school_day` save).
- `showAllClasses` is `true` for owner and admin and `false` for teacher,
  regardless of their own assigned-class count.
- A section `listMySections` returns that `attendance_day` has no matching
  row for falls back to zero students / not-taken rather than throwing.
- `dependency_unavailable` propagates independently from `listMySections`,
  the `attendance_day` RPC, and the caller's `profiles` read.
- `signInWithPassword` now **deletes** `acadigma_ui_mode`/`acadigma_text_size`
  (not merely skips setting them) when `fetchUiPreferences` fails — closing
  the shared-device gap `#64`'s review left half-open.

Measured from `pnpm --filter @acadigma/web build` + `node
scripts/check-bundle-budget.mjs` (the repo's real, CI-enforced gate — 250 kB
gzipped per route), after the review batch's `buttonVariants` extraction:

**Found and fixed during this Part:** `/app/home` first measured **276 kB**
gzipped — over budget, and 82 kB heavier than Part 1's own 194 kB baseline.
Root cause (D-405 item 8, full detail there): a Server Component importing
`@acadigma/ui/components/button` at all (any export, not only `asChild`)
pulls the entire `radix-ui` package into that route's client bundle, because
Next's RSC client-reference handling does not tree-shake past a barrel
package's own `"use client"` file. This is the third time this exact defect
has hit this codebase (`(school)/app/reports/runs/[id]/page.tsx`'s
`DOWNLOAD_LINK_CLASSNAME`, then D-305 item 8's results page, now this one).
Originally fixed by inlining the outline/primary `Button` classes as literal
strings in `essentials-row.tsx` and `home/page.tsx` (195 kB) — but those
literal copies had already drifted from the real `buttonVariants` (missing
D-57's `active:translate-y-px` press feedback and the `disabled`/
`aria-invalid` states). The review batch replaced them with `buttonVariants`
imported from a new radix-free `packages/ui/src/components/button-variants.ts`
(no `Slot`/`radix-ui` import, so the same barrel problem does not recur),
plus the essentials row's two new controls (Sign out, language switch) and
`HelpSheet`'s new footer button: **196 kB**, one kB over the pre-batch
number and still 54 kB under budget.

§5.5's own, stricter, spec-only budget (`< 150 KB gzipped` specifically for
`/app/home`) is **not met** (196 kB measured) — only the repository's actual
CI-enforced 250 kB budget is met. Recorded honestly rather than silently
treated as passing; see Known issues #2.

Lighthouse (LCP, INP): **not run** — the existing CI `lighthouse` job only
tests unauthenticated pages (`/`, `/login`); `/app/home` needs a signed-in
session the job has no fixture for. Adding one is a CI-infrastructure
change flagged for the lead (D-405, spec §11), not attempted here.
