## 1. Scope

**What this Part is.** `/app/home` is now the real class-by-class basic-mode
home instead of Part 1's placeholder: a today strip (greeting, date, "N roll
calls not taken" or "Nothing waiting"), one big `ClassBlock` per assignment
(class-teacher and/or subject-teacher, §2 footnote ²), an "All classes" block
for owner/admin, and an essentials row (Profile · Settings · Switch to full
app — Help lives in the top bar instead, D-405 item 6). Every basic screen
now sits inside `BasicShell` (Home + brand + Help, no sidebar/bottom nav),
applied to the whole `/app` shell in basic mode, not only `/app/home`
(D-405 item 5). Tapping a class opens the existing (not yet basic-sized)
roll call — the class hub is Part 3 (D-405 item 4). Also fixed: `#64`'s
review-flagged `signInWithPassword` gap (a `fetchUiPreferences` failure now
deletes both `ui_mode`/`text_size` cookies instead of leaving a stale one).

**Acceptance criteria covered** (from spec §9):

| #     | Criterion                                                    | Covered by                                                                                    |
| ----- | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| AC-4  | Teacher of one taken, one not-taken section sees both states | `packages/domain/src/basic-home/index.test.ts` (`buildClassBlocks`, `buildTodos`)             |
| AC-5  | No timetable → no "Next period" line                         | `TodayStripProps.nextPeriodLabel` is never populated this Part (structural, no wiring exists) |
| AC-9  | Every interactive element ≥ 56×56 px                         | `e2e/journeys/basic-home-tap-targets.spec.ts` (written; OQ-27, not run here)                  |

| AC-16 | Admin with no classes gets "All classes"                     | `packages/db/src/repositories/basic-home.test.ts` (`showAllClasses`); e2e above               |
| AC-17 | Deep link opens inside the basic shell with Home             | `basic-help-call-office.spec.ts`'s second test (`/app/classes/all` → Help → Home)             |

**Out of scope for this Part** (D-405, explicit): §2 footnote ²'s
`section_subjects` source (interim `exam_subjects.teacher_id` used instead,
PR #73 still open); the class hub (§4.5, Part 3) — a class tap goes to the
existing roll call; "Marks due" / outbox to-dos (F-AC-06 papers / F-ID-11,
neither exists); Part 4 voice hints; adding `/app/home` to the CI Lighthouse
job (needs an authenticated fixture the job does not have — flagged for the
lead, not guessed at).

**Risk areas:** (1) merging the interim `exam_subjects`-based assignment
source with the class-teacher source without double-counting or dropping a
section — covered by `buildClassBlocks`'/`getBasicHome`'s unit tests
including the "class teacher AND subject teacher of the same section" case.
(2) The basic-mode layout branch (`(school)/app/layout.tsx`) had to apply to
every `/app/*` route, not only `/app/home`, without breaking the full-mode
branch — proven by `pnpm --filter @acadigma/web build` succeeding for every
existing route and the full local unit suite staying green. (3) A real
production-build-only bundle-size regression (§6, D-405 item 8) that no unit
test or typecheck would have caught — found by actually running the build
and the repo's own budget script, not assumed passing.

### Notable cases proven

- A class-teacher assignment with no subject reads "Class teacher"; a
  subject-teacher assignment reads the subject name — `buildClassBlocks`
  tests.
- A teacher who is both class teacher AND a subject teacher of the same
  section gets **two** blocks, not one merged block —
  `buildClassBlocks`'s "gives a class teacher who also teaches a subject
  there two blocks" test.
- `taken`/`expected` are read from the saved session, not the live enrolled
  count, so they can legitimately differ — the "reports taken/expected from
  the saved session" test.
- A non-school day marks every block `not_school_day` even when a session
  exists (an `allow_non_school_day` save) — covered explicitly.
- `showAllClasses` is `true` for owner and admin and `false` for teacher,
  regardless of their own assigned-class count — `getBasicHome` test.
- A missing active membership row (should not happen once `requireShell` has
  run) degrades to "class-teacher sections only", not an error —
  `getBasicHome`'s "still returns ... when the membership lookup finds no
  active row" test.
- `dependency_unavailable` propagates from each of the three round trips
  (`attendance_day`, the caller's profile, `exam_subjects`) independently.
- `signInWithPassword` now **deletes** `acadigma_ui_mode`/`acadigma_text_size`
  (not merely skips setting them) when `fetchUiPreferences` fails — closing
  the shared-device gap `#64`'s review left half-open.

## 6. Performance

Measured from `pnpm --filter @acadigma/web build` + `node
scripts/check-bundle-budget.mjs` (the repo's real, CI-enforced gate — 250 kB
gzipped per route):

| Route              | Measured (gzipped)        | Budget | Result |
| ------------------ | ------------------------- | ------ | ------ |
| `/app/home`        | 195 kB                    | 250 kB | PASS   |
| `/app/classes/all` | 194 kB                    | 250 kB | PASS   |
| Whole app build    | succeeds, 40 static pages | —      | PASS   |

**Found and fixed during this Part:** `/app/home` first measured **276 kB**
gzipped — over budget, and 82 kB heavier than Part 1's own 194 kB baseline.
Root cause (D-405 item 8, full detail there): a Server Component importing
`@acadigma/ui/components/button` at all (any export, not only `asChild`)
pulls the entire `radix-ui` package into that route's client bundle, because
Next's RSC client-reference handling does not tree-shake past a barrel
package's own `"use client"` file. This is the third time this exact defect
has hit this codebase (`(school)/app/reports/runs/[id]/page.tsx`'s
`DOWNLOAD_LINK_CLASSNAME`, then D-305 item 8's results page, now this one).
Fixed the same documented way: inlined the outline/primary `Button` classes
as literal strings in `essentials-row.tsx` and `home/page.tsx` instead of
importing `Button`/`buttonVariants` from a server file, bringing it to
195 kB. `HelpSheet` was additionally moved behind `React.lazy`+`Suspense` in
`BasicShell` (fetched only once Help is tapped) for the same underlying
reason, though it turned out not to be this route's actual cost driver.

§5.5's own, stricter, spec-only budget (`< 150 KB gzipped` specifically for
`/app/home`) is **not met** (195 kB measured) — only the repository's actual
CI-enforced 250 kB budget is met. Recorded honestly rather than silently
treated as passing; see Known issues #2.

Lighthouse (LCP, INP): **not run** — the existing CI `lighthouse` job only
tests unauthenticated pages (`/`, `/login`); `/app/home` needs a signed-in
session the job has no fixture for. Adding one is a CI-infrastructure
change flagged for the lead (D-405, spec §11), not attempted here.
