## 1. Scope

**What this Part is.** The security boundary messaging will sit on: `channels`, `channel_members` and `messages`, every row tenant-scoped, a message visible only to its channel's members. Membership of the automatic channels (#general, #staff, one per section) is derived on read from roles, class teachers and subject teachers (D-311), so assigning a teacher puts them in the section channel in the same transaction and removing a member ends every channel at once. A trigger refuses a post from a non-member, into an archived channel or while muted. No user-visible screen yet — Part 2 builds the channel list and conversation.

**Acceptance criteria covered** (from spec §9):

| #     | Criterion                                             | Covered by                                                                                       |
| ----- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| AC-1  | School A member sees zero School B messages           | `59_messaging_schema.sql` C                                                                      |
| AC-2  | A parent cannot post (`forbidden`)                    | `59_…` B (no channel, no message) and D (`NOT_A_MEMBER`); the `/app/messages` redirect is Part 2 |
| AC-3  | A teacher not in #staff cannot see it                 | `59_…` B                                                                                         |
| AC-4  | An admin/owner cannot read a DM between two others    | `59_…` H                                                                                         |
| AC-5  | A removed member loses access immediately             | `59_…` F                                                                                         |
| AC-7  | Same `client_nonce` twice → one row                   | `59_…` D (unique constraint; the action's replay behaviour is Part 2)                            |
| AC-11 | A muted member's direct insert returns `muted`        | `59_…` G (`MUTED`, detail = end time); the disabled composer is Part 2                           |
| AC-12 | A teacher assigned to 7-B Physics appears in #class-… | `59_…` E — via `public.set_section_subjects`, same transaction                                   |

**Out of scope for this Part** — and where it is handled instead:

- Channel list, conversation, send action, edit/delete with tombstones → Part 2.
- Realtime publication, unread counts, read receipts, mentions, notifications → Part 3.
- Threads, reactions, attachments (`message_attachments`, `app.can_open_message_file`) → Part 4.
- Creating DMs (sorted-pair key enforcement) → Part 5; custom channels and moderation writes → Parts 5/8.

**Risk areas:** cross-tenant reads (the Base44 failure), a parent or removed member reaching chats, an owner reading others' DMs, forged sender/workspace, error-ordering oracles, D-300 read-only interplay, the new triggers on `workspaces`/`sections` breaking existing flows (whole pgTAP suite re-run).

### Specifically proven

- School B's owner sees zero School A channels and messages, and a post into School A — or into a random channel id — is the same `NOT_A_MEMBER` (no existence oracle).
- A forged `sender_id` is `NOT_A_MEMBER`; a forged `workspace_id` is refused by RLS.
- A parent is in no channel and reads no message; a teacher with no section sees #general only.
- A removed member loses every channel and message with no session change, and cannot post; a pending member is in no channel and cannot post; a member demoted to parent loses even a DM row they still hold.
- A person reads only their own `channel_members` rows — not even the owner reads another member's mute.
- A member of two schools cannot file a School A message under School B (`23503`, composite FK).
- An owner reads zero rows of a DM between two other members; `left_at` ends a custom channel.
- No client can update or delete a message, create a channel or write `channel_members` in Part 1; `anon` holds nothing; only `app.my_channel_ids()` is client-callable.
- A read-only school refuses a post (`PLAN_READ_ONLY`) and still reads.
