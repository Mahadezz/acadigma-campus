## 1. Scope

**What this Part is.** An owner or admin opens Exams and creates "Half-Yearly 2026" for the year's sections and the subjects they pick. That creates one paper per section × subject, with 100 full marks and 33 pass marks. They then set each paper's date and marks and move the exam along its status chain. The exam keeps a copy of the grading policy it was created with.

| Criterion                                                                  | Covered by                                             |
| -------------------------------------------------------------------------- | ------------------------------------------------------ |
| Papers are created per section × subject in one transaction                | `53_exams.sql` A; `exams.spec.ts`                      |
| Pass marks default from the pass mark (33 of 100)                          | `53_exams.sql` A; `exams.test.ts` (`defaultPassMarks`) |
| The grading policy is snapshotted and never follows a later scale edit     | `53_exams.sql` B                                       |
| §5.12: no cycling, no skipping, reversals need a reason                    | `53_exams.sql` C; `exams.test.ts`; `actions.test.ts`   |
| Owner/admin write; teacher/staff read; parents none; other schools nothing | `53_exams.sql` E; `actions.test.ts`                    |
| Read-only schools cannot create exams                                      | `53_exams.sql` F; `actions.test.ts`                    |

**Out of scope (D-303):** terms, `section_subjects`, components, aggregate exams, calendar events, question-paper upload, idempotency keys and rate limits.
