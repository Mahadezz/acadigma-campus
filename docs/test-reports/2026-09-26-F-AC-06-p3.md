## 1. Scope

A teacher opens a paper on a phone, types each student's mark with Enter moving to the next student (the keypad stays up), marks Absent/Exempt with a chip or A/E, sees "24/40", and saves once; an out-of-range value stays on screen with an inline error while every valid row saves. The owner names each paper's teacher on the exam page and sees "n/m marked" per paper. Publish is refused until every enrolled student in every paper has a mark or is absent/exempt.

## 7. Known issues

1. No offline queue or autosave draft: a save with no signal fails with "try again" and keeps the marks and the idempotency key on screen, so the retry replays the same save (D-71 / Part 4; the owner's per-cell "later edit wins" rule is recorded).
2. The live journeys, this one included, run in neither CI nor locally until OQ-27 gives CI a seeded account; the screen was verified through the preview route and unit tests instead.
3. No entry date window (`entry_opens_on/closes_on`), no submit, no lock/unlock of a single paper, no marks-progress screen (Part 4).
4. Desktop has no paste-a-column or distribution histogram; no components (Written/MCQ), `withheld` or remarks.
5. Teachers reach the screen from the exam page; there is no "my papers" list or dashboard card.
6. `MarkCell` (packages/ui) clamps out-of-range values, which AC12 forbids, and DESIGN-SYSTEM §5.2 describes a one-student custom keypad; this screen follows the spec with `ui/input` instead. For the design lane to reconcile.
7. On a phone the sticky bar sits 56 px above the bottom edge to clear the shell's bottom nav; the preview screenshots have no nav, so a gap shows there.
8. Fixed on the way: `exam_subjects` had no FK to `sections`, so `getExam`'s `sections(...)` embed had no PostgREST relationship; a composite FK is added (D-304 item 9).
