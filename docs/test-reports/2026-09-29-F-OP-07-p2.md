## 1. Scope

**What this Part is.** An owner or admin can now open Settings → Academic and: create an academic year and set it current (with a confirmation naming the consequences, audited both ways); add or delete a term inside a year (refused if it falls outside the year or overlaps another term); edit a year's exam weighting as a live percentage sum, blocked from saving unless it adds to 100 or is empty; and edit the pass-mark, GPA-zero rule, rank-by and grade-scale-code fields that every new exam snapshots at creation.

**Acceptance criteria covered** (spec §9, "Academic"):

| #     | Criterion                                                                            | Covered by                                                                                                     |
| ----- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| AC-7  | Exactly one `is_current = true`; switching asks for confirmation naming consequences | `academic_years_one_current` partial unique index; `47_terms.sql` #7-9; `academic-manager.tsx` dialog          |
| AC-8  | A 3-day gap inside a year is refused, naming the dates                               | **Partial** — see D-210 point 3 and §8. Overlap and out-of-range are refused; a gap is not.                    |
| AC-9  | Weights summing to 90 with weighting on are refused                                  | `checkExamWeights`, `terms.test.ts` (domain), `academic-years.test.ts` (repo, submit disabled client-side too) |
| AC-10 | A `pass_mark_percent` change affects new exams only, old results keep their scale    | `app.tg_exams_snapshot_grading` (pre-existing, D-303) reads `academic_settings` at exam creation only          |

**Out of scope for this Part** — and where it is handled instead:

- Attendance policy live preview (spec Part 3) — not started.
- Modules, ID patterns, danger zone (spec Part 6) — not started.
- Grade scale editor (spec Part 4) and calendar (spec Part 5) — already shipped separately under F-AC-06 Part 1 (D-302, `/app/settings/grade-scale`) and F-AC-11 Part 1 (D-202, `/app/settings/calendar`).
- Full-year gap detection for terms, "copy last year's terms" on year creation, promotion rule / rank scope / parent-visibility fields — see DECISION-LOG D-210 and spec §11.10 for the reasoning.

**Risk areas** — where the testing effort went:

- The `set_current_academic_year` RPC's atomic swap under the `academic_years_one_current` partial unique index (a bad implementation could momentarily violate it, or leave zero/two years current on a partial failure).
- Tenant isolation and role escalation on the new `terms` table, and on the RPC (an owner of school B must not be able to touch school A's current year).
- The client actually re-rendering after a save invoked as a plain server-action call, not a `<form action>` (`router.refresh()` — a real bug caught and fixed while building this Part).
- A parallel ECC review round (Opus `security-reviewer`, `typescript-reviewer`, `react-reviewer`, `engineering-database-optimizer`, plus self `ponytail-review`) on this diff before marking the PR ready caught and fixed a real HIGH: `WeightingPanel` kept a previous year's typed-in weights in local state after switching years (no `key` forcing a remount), which would have silently folded stale exam-weight values into the new year's save payload. See DECISION-LOG D-210's "Review of PR #110" note for the full list (also: a shared `useTransition` disabling every tab's button while any one tab saved; a missing exam-ownership check on `updateExamWeights`; a dead `sort_order` column; a concurrency race in `set_current_academic_year` fixed with an advisory lock).

**Notable cases proven:**

- An invalid academic-year range (ends before starts, over 730 days) is refused before any database write (`createAcademicYear` unit test asserts no `insert` call reached the fake client).
- A term outside its year's range, and a term overlapping an existing one, are both refused before the insert (same pattern — verified no `insert` call happened).
- `setCurrentAcademicYear`'s "academic year not found" database message maps to `not_found`, any other RPC error maps to `dependency_unavailable` (not leaked to the client verbatim).
- `checkExamWeights` treats an empty map as valid (weighting off) and requires an exact 100 sum otherwise, with float tolerance for values like `33.33 × 3`.
- `deleteTerm` and `updateExamWeights` both return `not_found` when zero rows were touched (another school's id, or already gone) rather than silently succeeding.
