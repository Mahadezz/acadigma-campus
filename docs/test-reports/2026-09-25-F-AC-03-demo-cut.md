## 1. Scope

A class teacher opens their class on a phone, taps "Mark all present" (সবাই উপস্থিত), flips the absentees on the segmented toggle and saves; the owner sees which classes are marked, by whom and when, and the school's rate so far, on `/app/attendance` and on the dashboard. See D-104 for what is deferred (offline queue, locking, register, alerts, reminders, notifications).

## 4. Database (pgTAP)

`34_attendance.sql` **47/47** locally; every other file passes (`12_function_grants_invariant.sql` with `save_attendance` and `attendance_day` allow-listed). `51_readonly_join_and_seed.sql` uses psql meta-commands and does not run in the local harness (pre-existing; it runs in CI). The fixture school works all seven days and every date is relative to the school's today, so the file passes on any weekday.

- the class teacher's save: counts, expected 3, `bulk_marked_by`/`bulk_marked_at`, one record per student; a replay returns the stored session; a second save without the loaded version is `CONFLICT`; with it, the day updates and only the changed record is audited (no per-student insert audit);
- refusals: `UNMARKED_STUDENTS`, `STUDENT_NOT_ENROLLED`, unknown status, `FUTURE_DATE`, `OUTSIDE_EDIT_WINDOW` for a teacher, `NOT_ASSIGNED` for another section or a non-class teacher, `FORBIDDEN` for staff; the owner may mark beyond the window (stamped) and any section; a holiday is `NOT_SCHOOL_DAY` unless confirmed; no direct INSERT/UPDATE even for an owner;
- rules: one session per section per day, one record per student per session, no session on another school's section, no record under another school;
- visibility: teachers and staff read, a parent member reads nothing, another school's owner reads nothing, cannot save here or via their own school, and gets an empty Today;
- Today overview: both sections, the teacher's own flagged, today's counts, enrolled counts;
- `app.attendance_pct`: 90.91, 86.36 with half day off, 0 with no records; read-only mode refuses a save; anon has no privilege.

## 5. End to end

Journey `apps/web/e2e/journeys/take-attendance.spec.ts` (open the first class, mark all present, flip one to absent, save within 30 s, back to Today; axe on each view) is committed and skip-gated on OQ-27. **Not run live**: the live database gets this migration only after merge.

Instead each view was rendered locally through a throwaway preview route (not committed; content only, without the app shell) with 40 students — Today as owner and as teacher, the roll call empty, after "Mark all present" + 3 flips, on a holiday, and read-only — in English and Bangla at 360×800 and 1280×800 (24 runs), checked with `@axe-core/playwright` (WCAG 2.1 A/AA), a scan for targets under 44 px and a horizontal-scroll check: **0 axe violations, no horizontal scroll**. "Mark all present" + 3 flips took 281–430 ms of scripted clicks. Under 44 px: the app-wide "Skip to content" link and the holiday-confirmation checkbox (16 px, inside a 44 px clickable label).

## 7. Known issues

1. No offline queue: a save with no signal fails with "try again" and keeps the marks on screen (Part 7).
2. A concurrent save returns `CONFLICT` ("reload") rather than a keep/apply/merge sheet.
3. The half-day weight is on/off (DATA-MODEL policy), not 0.5 (AC6).
4. No reminders or absent-guardian notifications; no register, alerts, locking or correction requests.
5. On a phone the sticky Save bar sits 56 px above the bottom edge to clear the shell's bottom nav; the preview screenshots have no nav, so a gap shows there.
6. Screenshots come from a local preview, not the live demo login.
