## 1. Scope

**What this Part is.** The class hub — `/app/classes/[sectionId]` — the screen the owner's own walkthrough described: "they can just press a class, enter the class; there will be all the handouts, marking, printing, attendance, lesson planner, routine all in one block." This Part ships the four tabs that already have a real page to reuse: **Attendance** (the existing roll call, at basic sizes, with a plain-language `ConfirmSheet` before every save and a 30-second post-save Undo), **Marks** (this section's papers the caller teaches, n/N entered, tap through to the existing marks entry screen — the first time marks are reachable from basic mode), **Students** (this section's roster, Bangla names via `BnEnText`; a row opens the student's profile, read-only), and **Print** (spec §4.5's literal row: "Print attendance register", "Print mark sheet" for this class, plus the report cards D-406 originally shipped — see the review-batch note below). A caller not assigned to a section (and not owner/admin) sees "This class is not on your list," with no student data sent to the browser. Class blocks on the home screen and the "All classes" list now open the hub instead of the roll call directly.

**Acceptance criteria covered** (spec §9):

**Out of scope for this Part** (per the builder brief for this Part and the spec's own dependency notes):

- **"Earlier days" (the past-session list)** in the Attendance tab — no repository anywhere in the codebase (F-AC-03 included) lists a section's past sessions yet. The brief's own wording for this Part was "today's roll call inline or one tap to it," which ships.
- **The Lighthouse hub URL** (spec §8 Part 3's own "a hub URL added to the existing Lighthouse job") — the same reason `/app/home` was not added in Part 2 (D-405 item, "the existing CI `lighthouse` job only tests unauthenticated pages"): the class hub needs an authenticated session too, which that job has no fixture for. Recorded as a deviation here and in DECISION-LOG D-406, not built quietly.
- **Routine, Handouts, Lesson plan, Homework tabs** — each is its own future feature Part (F-AC-05, F-TE-05, F-TE-01, F-AC-07), added to `CLASS_HUB_TABS` when it ships, per spec §8's closing note.
- **Part 4 (voice hints)** — untouched by this Part.

**Review batch (2026-09-27): the stale "F-OP-03 Part 6 not merged" claim.** D-406's original text said register/mark-sheet printing was omitted because Part 6 wasn't merged — Part 6 merged the same day (#76, D-208). `print-tab.tsx` now also renders `GenerateAttendanceRegisterButton` (this month's register, always available, no exam needed) and `GenerateMarkSheetButton` (tied to the latest exam, alongside the report-card actions), both already `OnlineOnly`-wrapped inside their own components (F-ID-11 §4.9, D-308) — no new wrapping needed here. The report-card actions D-406 originally shipped stay; spec §4.5's Print row doesn't name them, but nothing asked to remove already-working, already-reviewed functionality, so the smaller diff was to add what was missing rather than replace what shipped.

**Risk areas:** (1) the hub's own assignment gate (`NOT_ASSIGNED`) had to be strictly separate from, and checked before, every tab's own permission. **Security wording fixed in review (2026-09-27):** the original text here said a bug "would leak another teacher's class data" — overstated. Within one school, RLS is role-scoped, not section-scoped (`students_select`, `attendance_sessions_select`/`attendance_records_select` all read `app.has_role(workspace_id, ...)`, no section check at all): any teacher can already read any section's roster and attendance directly through the database, the same access the full (non-basic) app already gives every teacher. `NOT_ASSIGNED` is a UX narrowing consistent with that existing app-wide convention, not a data-security boundary — a bug here would make the _hub_ behave inconsistently with what its caller can already reach elsewhere, not expose anything RLS doesn't already allow. Still worth the unit test and e2e journey it got, for correctness, not because it's a security boundary. (2) `exam_subjects.teacher_id`/`sections.class_teacher_id` are `workspace_members.id`, not `ctx.userId` — the same trap `getMarkSheet` already had to resolve; `listSectionPapers` follows the identical two-query resolve-then-compare shape. (3) the route's own bundle size: reusing `RollCall` (which already pulls in Radix `Sheet`/`Checkbox`) plus a tabbed interface pushed the page over the repo's 250 kB gzipped budget on the first pass — see §6.

**What this found, and what got fixed as a direct result (not from reading the code, from watching it run):**

- **A real a11y regression.** `expectNoA11yViolations` failed on the class hub: the new `ConfirmSheet` `next/dynamic` `loading` fallback was an icon-only `<button>` with no accessible name. First fix (round 2) added an sr-only label; a further lead review (round 3) pointed out `ConfirmSheet` renders nothing at all while `open` is false, so a visible fallback — labelled or not — was a stray element that was never there before. Corrected to `loading: () => null`, matching what the resolved component itself renders at that point; the axe violation is gone because there is no button in that state at all, not because it has a name now.
- **A real layout bug: tab labels overflowing the grey bar.** `TabsList`'s own `group-data-[orientation=horizontal]/tabs:h-9` (packages/ui) has higher specificity than a plain `h-auto` utility passed in from the caller (an attribute-selector rule beats a class-only one), so the fixed 36px box let the icon+label content spill out below it, overlapping the date line. Fixed caller-side with Tailwind's important suffix, `h-auto!` — `packages/ui` itself untouched.
- **A real layout bug: the "Half day" (½) segment still clipped at 1280px, found across two review rounds.** Round 2 blamed `class-hub-view.tsx`'s outer `max-w-2xl` (narrower than `RollCall`'s own `max-w-5xl`) and widened it — the screenshot looked right, but the real cause, caught by a closer lead review of the same screenshot, was `AttendanceToggle`'s own fixed `sm:w-72` (288px): 5 segments at basic size's `min-w-16` need >= 320px, so `overflow-hidden` clipped the 5th regardless of how much room the page gave it. Fixed at the source (`roll-call.tsx`: `sm:w-80` only when `basic`, default size's narrower segments untouched). Reverting the outer `max-w-5xl` back to `max-w-2xl` was tried next, on the reasoning that the real fix made it redundant — a real 1280px screenshot immediately showed why not: the 2-column grid's ~304px column cannot fit a 320px `shrink-0` toggle, so the name div (`min-w-0`, free to shrink) collapsed to nothing and every student's name vanished. `max-w-5xl` stays; both fixes were needed together, not one or the other.
- **A real duplicate-heading bug.** The class hub's own header and `RollCall`'s own header both rendered an `<h1>` with the same class name — two `<h1>`s on one page. Fixed: `RollCall` renders that title as a `<h1>` only when `basic` is false (the plain `/app/attendance/[sectionId]` page, unchanged); as a `<p>` in the hub, where the page's one `<h1>` is already the hub's own. Verified by counting `<h1>` elements on the live page (2: the shell's own brand-name `<h1>`, unrelated, plus exactly one "Class 6 – ক"), not just by re-reading the diff.
- **A real, pre-existing test bug**, found chasing a `56×56` failure that survived both layout fixes above: the shell's own `<a href="#main">Skip to content</a>` is `sr-only` until keyboard focus (a real, correct a11y pattern) but still has a non-null, sub-56px bounding box, and `basic-class-hub.spec.ts`'s target-size loop had no exclusion for it (`basic-home-tap-targets.spec.ts`, right next to it, already did — `.filter({ hasNotText: "Skip to content" })`). Matched that existing pattern exactly rather than inventing a new one.
- **After every fix above, real passing evidence exists for**: sign-in as owner, turning basic mode on, opening the hub from "All classes", all four tabs present with no "coming-soon" tab and no overflow, roving-tabindex keyboard navigation (Left/Right/Home/End), "Mark all present" → Save → `ConfirmSheet` naming the plain-language count → "Yes, save" → "Saved: N present, M absent", the 5-segment `AttendanceToggle` rendering in full at 1280×800, one `<h1>`, and the 56px target-size check itself passing on both projects — captured as real screenshots and a real passing test run, not reasoning alone (numbers below).

**Found and fixed during this Part:** the first version measured **257 kB**, over budget. Root cause: Radix `Tabs` plus all three non-Attendance tab components bundled eagerly into the page. `next/dynamic(() => import(...), { ssr: false })` on Marks/Students/Print brought it to 244 kB.

**Review round 1 (2026-09-27, per the owner's shadcn-first rule):** swapped the hand-rolled tablist back for real `@acadigma/ui/components/tabs` (Radix) and rebuilt — 251 kB gzipped, 1 kB over the gate (245 kB for the hand-rolled version, both shifted slightly after the `origin/main` merge). Shipped the hand-rolled tablist for that reason, adding roving `tabindex` + Left/Right/Home/End by hand (WAI-ARIA APG "Tabs") since it had shipped with no keyboard handling at all.

**Lead decision, same review (2026-09-27):** reversed round 1. The owner's standing rule is no hand-rolled replacements for a component shadcn already has, and round 1 itself proved the reason for that rule — the hand-rolled tablist shipped with a real a11y gap. A 1 kB overshoot is the smaller risk. Radix `Tabs` ships; the hand-rolled tablist and its roving-tabindex code are deleted. The 1 kB (and then some) was won back a different way, without new hand-rolled UI: `RollCall`'s `ConfirmSheet` — a `Sheet` that only opens after Save is tapped, not needed for the tab's initial paint — moved behind `next/dynamic(..., { ssr: false })`, the same treatment already applied to Marks/Students/Print. Final: **241 kB** on this route, and **234 kB** on the plain `/app/attendance/[sectionId]` as a side effect (that route pays the same `ConfirmSheet` import cost even though `basic=false` never opens it). `basic-class-hub.spec.ts`'s keyboard assertions (added in round 1) are unchanged and pass against Radix `Tabs` unmodified — it implements the same WAI-ARIA APG contract natively. `roll-call.test.tsx`'s four basic-mode tests were updated to `await screen.findByRole(...)` where they interact with `ConfirmSheet`, since it now mounts one tick after Save instead of synchronously; all 12 tests in that file pass. Full detail in DECISION-LOG D-406's addenda.

Lighthouse: not run — the existing CI `lighthouse` job only tests unauthenticated pages (`/`, `/login`), same limitation Part 2's report already recorded for `/app/home`.
