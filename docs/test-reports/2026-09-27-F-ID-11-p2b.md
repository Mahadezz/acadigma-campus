## 1. Scope

**What this Part is.** When a colleague saved a class after a teacher took the roll offline, she gets "Compare and choose": who saved when, only the students that differ, theirs or mine for each, and Keep theirs / Use mine / Save my choices — nothing is overwritten until she chooses. A roll call taken offline inside its correction window that reaches the server up to 7 days later creates the missing register, marked "Sent late from offline". An expired session pauses the queue ("Sign in again to send…") and the same user signing in resumes it. Another account's queue on a shared phone is never sent, shown (beyond a count) or deleted by whoever signs in; a deleted or banned account's queue is removed.

**Risk areas:** a late save that edits an existing register; clock tampering widening the late window; one person's queue sent or deleted under another's session; an expired session silently dropping work.

### Notable cases proven

- `unauthenticated` pauses the run instead of retrying; a signed-out check with items waiting pauses too; the same user's next confirmed check resumes.
- `conflict-sheet.test.tsx`: only differing students shown, nothing written on open; Save my choices sends her pick and theirs for the rest on their version; Use mine; Keep theirs deletes only her item; an unreadable register offers no save (mutating the default pick fails it).
- `resolveConflict` rewrites the conflict item with the chosen records on the colleague's `updated_at` under a new idempotency key and sends it through the outbox.
- `capturedAt` is fixed when the save is queued (device time + server clock offset), so every replay is the same payload.
- The session route answers `revoked` only for `user_not_found` / `user_banned`; any other signed-out answer keeps the queue.
- Real PostgREST: a replay with `capturedAt` stores `captured_at` and `queued_offline`; a late replay with no register creates one with `synced_late`.

## 7. Security checks

| Check                  | Result                                      |
| ---------------------- | ------------------------------------------- |
| CI `security`, Semgrep | pass                                        |
| New grants             | none (functions replaced, grants unchanged) |

- `captured_at` is bounded on every save, any role (≥ start of the session date, ≤ `now()` + 5 min, else `VALIDATION`), so a forged time cannot fake `queued_offline` or the capture time in the audit (#93 review; pgTAP for teacher in-window and owner saves, future and 1990).
- **Lock:** adding the STORED generated column `queued_offline` rewrites `attendance_sessions` under ACCESS EXCLUSIVE. Live holds only demo data, so this is accepted (also in the migration header).
- A late save can only create a register, never edit one (checked under the section row lock); the bounds use the server clock; captured vs arrival time is in the audit.
- Another account's queue is never sent (per-user database, session check, `queuedFor` refused server-side), shown beyond a count, or deleted by the next user; it expires after 14 days.
- Sign-out uses the server's `ctx.userId`.
