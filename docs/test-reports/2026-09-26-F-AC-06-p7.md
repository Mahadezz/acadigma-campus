## 1. Scope

An owner or admin presses "Publish" on a marks-locked exam, sees what publishing does, withholds any student with a reason, and publishes. Nothing incomplete can be published, each result's report card is frozen in the database, a later rename changes nothing, and "Unpublish" (with a reason) hides results again. A parent linked to a child sees that child's published result on `/family` and downloads the report card. **Parents can sign in and reach `/family`, but no parent can be linked to a child in the product until F-AC-02 Part 4's invite flow ships, so the parent half is proven by pgTAP, not end to end.**

| #           | Criterion                                                                    | Covered by                                                                                                                          |
| ----------- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| AC15        | Unpublished → a parent reads nothing; published → exactly their own child    | `56_` §A "before publishing…"; §D one result (S1) and its 2 lines; §E 0 after unpublish, 1 after republish                          |
| AC15        | …and no classmate's                                                          | `56_` §D: P1 does not read S2 (another family, same section); P2 (S2 withheld) reads 0                                              |
| AC16        | Rename a subject after publishing → the issued card still reads the old name | `56_` §C: "Science 56" → "General Science 56" and section A → Alpha; the frozen card is unchanged                                   |
| §4.5        | Publish refused with incomplete results                                      | `56_` §A: `MARKS_NOT_LOCKED`, `MARKS_INCOMPLETE` (D-304 gate), `NOT_COMPUTED`, `INCOMPLETE_PRESENT` (stale results)                 |
| §4.5        | Withhold individual students; audit with the withheld list                   | `56_` §B: `{"published": 2, "withheld": 1}`, reason kept, card frozen `withheld` (no GPA/grade/rank), one `results.published` event |
| §4.5        | Unpublish audited, frozen payload retained                                   | `56_` §E: `{"unpublished": 3, "reason": "A mark was wrong"}`, 3 payloads kept                                                       |
| §5.14       | Every reprint reads the frozen payload; no recompute after publishing        | `results.test.ts` (frozen card returned, nothing else read); `56_` §C `compute_results` → `MARKS_NOT_LOCKED`                        |
| Roles       | Only owner/admin publish; read-only refused                                  | `56_` §A (teacher, staff, parent, another school → `FORBIDDEN`; `PLAN_READ_ONLY`); `exams/actions.test.ts`                          |
| F-AC-10 AC3 | Another child's card by id is not-found                                      | `api/family/report-card/route.test.ts` (seam `not_found` → 404, nothing rendered; non-parent 403; bad id 422)                       |

Out of scope (D-306): the `result.published` notification (F-ID-07 has no delivery; `TODO(D-306)`), the invite/link flow (F-AC-02 Part 4), F-AC-10's switcher/tab strip and security-definer views (Parts 1–2), releasing one withheld student without unpublishing.

Risk areas: a parent reading anything beyond their own child's published result (the RLS policy is the boundary until F-AC-10 Part 2's views); a published card changing under a family; publishing something incomplete through the plain status step (the trigger covers both paths).
