## 1. Scope

**What this Part is.** The product now has one answer to "is this a school day?". `app.is_school_day(workspace_id, date)` applies a working-day override first, then the school's weekly pattern, then its holidays. `app.school_days` and `app.school_day_count` count school days over a range, which attendance, leave and analytics will use as their denominator. Owners and admins can list, add and remove holidays at `/app/settings/calendar`. Teachers and staff can see the list but cannot change it.

**Acceptance criteria covered** (spec §9):

| #    | Criterion                                                  | Covered by                                                         |
| ---- | ---------------------------------------------------------- | ------------------------------------------------------------------ |
| AC1  | Friday false on Sat–Thu; an override makes it true         | `41_school_calendar.sql` §1 and §4                                 |
| AC2  | A holiday over 3 days drops the month's count by exactly 3 | `41_school_calendar.sql` §4: April 2026 goes 26 → 23               |
| AC13 | An override without a reason is refused                    | `41_school_calendar.sql` §2 (`working_day_overrides_reason_check`) |
| AC17 | Workspace A sees no row of workspace B                     | `41_school_calendar.sql` §3 (read, update, delete, insert)         |

Not in this cut (D-202): AC3 (scoped holidays), AC4 (TS parity), AC5-AC12 and AC14-AC18 (other features, events, views, publishing).

## 4. Database (pgTAP)

`supabase/tests/41_school_calendar.sql`, **52 assertions** after the PR #43 review batch (the first version's 31 passed in CI, [run 36087322108](https://github.com/Mahadezz/acadigma-campus/actions/runs/36087322108/job/107922033287)). The review-batch run's result is on the PR's `db` check. Not run locally (no Docker).

| Table                   | Isolation                                  | Escalation                                                       |
| ----------------------- | ------------------------------------------ | ---------------------------------------------------------------- |
| `holidays`              | read 0, update 0, delete 0, insert refused | teacher insert refused, teacher delete affects 0, parent reads 0 |
| `working_day_overrides` | covered by the same policy shape           | teacher insert refused                                           |

Also asserted: range and reason checks, `workspace_id` immutable, a `holidays.insert` audit row, and `PLAN_READ_ONLY` on insert and delete in a read-only workspace. For `is_school_day`: override beats the weekly pattern, override beats a holiday, an override can close a normal day, a Mon–Fri school reads its own pattern, and a teacher's RLS-filtered count equals postgres's. Added by the review batch (D-203): a **parent** gets postgres's answer for a holiday, an override-opened Friday and the April count; a member of another school gets `NULL` from `is_school_day` and `FORBIDDEN` from the count; School B cannot read, update or delete School A's overrides; a teacher's update or delete of an override affects zero rows; `created_by` is immutable on both tables; a duplicate (name + first day) is refused; a holiday across the year end and two overlapping holidays count correctly; the 365/366-day cap; the 731/732-date range bound; the six audit catalogue rows exist; no policy names the parent role.
