## 1. Scope

**What this Part is.** A teacher, admin or owner can now open `/app/reports`, tap "Generate sample document", and download a real PDF a minute later — with the school's own name and header lines (from `school_profiles`, via the same `renderHeaderLine` F-OP-07's branding preview uses), correctly-shaped Bengali text (including conjuncts), and real page numbering. Before this Part, `packages/pdf` did not exist and `report_runs` had no schema at all.

**Acceptance criteria covered** (from spec §9; addendum items 7-13 in the spec record the deviations):

| #     | Criterion                                                          | Covered by                                                                  |
| ----- | ------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| AC-1  | Bengali school name renders with correct conjuncts; no "TeachFlow" | `packages/pdf/src/golden.test.ts`, `banned-strings.test.ts`                 |
| AC-2  | Two schools' headers differ, no hardcoded address                  | `golden.test.ts` "two different school fixtures..."                         |
| AC-3  | `report_locale='bn'` → Bengali digits on page numbers/percentages  | `golden.test.ts` "prints Bengali digits...", `format.test.ts`               |
| AC-4  | Every page shows "Page i of n" correctly                           | `document-shell.tsx` real `render` prop; `golden.test.ts`                   |
| AC-19 | Identical request + unchanged data → same run, no re-render        | `reports.test.ts` "on a duplicate idempotency key...", `40_report_runs.sql` |
| AC-21 | A render that throws sets `failed` with a non-empty `error_code`   | `actions.ts` `renderSampleRun` catch block; `actions.test.ts`               |

**Out of scope for this Part** (spec §11 addendum items 7-13, decisions D-204/D-205):

- Every report kind except `'sample'` (report_card, mark_sheet, ... — need F-AC-0x exam/marks data that does not exist yet).
- The cron drainer and Realtime progress (spec's own "immediate in-request kick for single-item runs" allowance is what Parts 1-2 build instead).
- Persisting the rendered PDF to Storage / a `files` row, and the signed-URL download + access log (`file_access_log`) — `files`/Storage has no consuming code anywhere in the repo yet (no `storage.objects` RLS, no `/api/files/[id]`); building that from scratch was judged out of this Part's scope. `GET /api/pdf/[runId]` re-renders instead.
- The 7-card report-type gallery, comments/AI, bulk rendering, publish, registers, mark sheets, ID cards — all later Parts (3-8).
- Plan-gating's exact error code: this repo's `ApiErrorCode` enum has no `plan_required`; reused `payment_required`.

**Risk areas** — where the testing effort went:

- **Bengali text fidelity.** This is the load-bearing risk for the whole feature. Found and fixed a real bug during development: `document-shell.tsx`'s footer/watermark and `sample.tsx`'s body text were plain `<Text>` (using the page's default Latin-only font), producing mojibake for Bengali digits and conjuncts — fixed by routing every piece of possibly-Bengali text through a script-aware `ScriptText` helper. Verified by rendering the fixture to an actual `.pdf` and reading it visually (not just asserting on the JSX tree).
- **A second, real finding, left open (not silently worked around):** `@react-pdf/renderer`'s `fontkit`/`pdfkit` shape Bengali conjuncts correctly for on-page rendering (confirmed visually), but the **ToUnicode CMap for a reordered/ligated glyph does not reliably round-trip to the original logical-order codepoints** on text extraction (copy/paste, search, `pdf-parse`). See `golden.test.ts`'s header comment and Known Issue #1 below.
- Cross-tenant isolation on `report_runs`/`report_run_items` (pgTAP) and the download route (no client UPDATE grant at all; RLS-scoped reads only).
- The idempotency race (duplicate key on a live run vs. a failed one).

### Notable cases proven

- Invalid input (`params.kind` not `"sample"`, missing `locale`) rejected before `requireWorkspace()` is ever called — `actions.test.ts`.
- A role without `report.render.sample` is refused before the plan check, `requireWritable`, or the repository — `actions.test.ts`.
- A Free-plan workspace (no `reports` module) is refused with `payment_required` before `requireWritable` or the repository — `actions.test.ts`.
- An idempotent replay of an existing `queued|rendering|ready` run does not call `withServiceRole` again (no re-render) — `actions.test.ts`.
- `GET /api/pdf/[runId]`: an invalid id never resolves a workspace context; a denied role never touches `report_runs`; a `not_found` run (RLS-invisible or genuinely missing — indistinguishable on purpose) never renders; a non-`ready` run never renders — `route.test.ts`.
- `computeIdempotencyKey` is stable under key reordering, differs by workspace/locale/params, and correctly buckets/un-buckets across the 10-minute fallback window (spec §11 OQ3) — `reports.test.ts`.
- A duplicate `(workspace_id, idempotency_key)` insert against a _live_ run returns the existing run; against a _failed_ run, a fresh insert succeeds — `reports.test.ts`, `40_report_runs.sql`.

## 4. Database (pgTAP)

**Not run locally** — this repository's pgTAP suite requires a live Postgres (`supabase test db`), and local development in this environment has no Supabase credentials or Docker (`no Docker` per CLAUDE.md). `40_report_runs.sql` was written and reviewed against the same conventions as `20_staff_schema.sql`/`03_role_escalation.sql`, but its 19 assertions have not been executed. **CI-only**; results will be pasted here after the `db` job runs.

| Table              | Isolation assertions | Escalation assertions                                | Result  | File                                |
| ------------------ | -------------------- | ---------------------------------------------------- | ------- | ----------------------------------- |
| `report_runs`      | yes (School A/B)     | yes (teacher-vs-teacher, insert-attribution forgery) | CI-only | `supabase/tests/40_report_runs.sql` |
| `report_run_items` | yes (via parent run) | yes (no INSERT grant at all)                         | CI-only | `supabase/tests/40_report_runs.sql` |

**`coverage.sql`:** not run locally (same reason); `scripts/check-coverage-test-files.mjs` (static, no DB needed) passes: "Coverage OK — 25 workspace_id tables; 25 named in a supabase/tests/*.sql file, 0 tracked in KNOWN_GAPS."

### Specifically proven (by inspection of the written assertions, pending CI confirmation)

- A user in School B sees zero rows of School A's `report_runs`, by direct select.
- No `authenticated` role — not even the workspace owner — can `UPDATE` or `DELETE` a `report_runs` row (no grant at all, not just an RLS gap).
- A teacher cannot insert a run attributed to a colleague (`requested_by` forgery, RLS `WITH CHECK`).
- `report_run_items` visibility follows the parent run's requester/role, and has no `authenticated` INSERT grant at all.
