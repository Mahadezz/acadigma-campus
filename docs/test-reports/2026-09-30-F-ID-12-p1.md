## 1. Scope

**What this Part is.** `campus.acadigma.com/` is rebuilt in acadigma.com's look (read from `acadigma-website` `origin/main`, not invented). It names only live features, offers **Sign in** and **Create account**, and has a "Get the app" chooser (`#get-the-app`) with Web · Android · iPhone · Windows · Mac tabs. Each tab gives the browser's own PWA install steps; a real Install button appears only when the browser fires `beforeinstallprompt`; store/desktop builds say "coming later". An "Acadigma apps" row shows Campus (you are here), Parents, Students and Ledger (coming soon, as on acadigma.com), each linking to `acadigma.com/<product>`. The `(auth)` layout gets the same texture and a one-line footer. No auth form, action or validation changed. No migration.

## 7. Known issues

1. **acadigma.com and this page disagree on Parents' status only in detail**: both say "coming soon"; this page adds that invited parents can already sign in to Campus for published results and report cards (true today, `/family`). The website says parent accounts are "not available yet", which is now inaccurate.
2. **AC-4 is not automated** (see §1).
3. **The website's motion is not ported**: no animated hero mark, flip-words, pointer spotlight or parallax footer (D-410 §2).
4. **Install steps name browser menu labels in English** in both languages (Chrome/Safari show them in the device's language); the Bengali copy keeps the English label so it matches an English-language browser.
5. Signed-in visitors see the same front door (no redirect), by design.
6. **`/` is slower than the old page under Lighthouse's simulation** (best LCP 3050 ms vs 2448 ms; the warn bound is 2500 ms, the error bound 3500 ms). The LCP element is now the hero's value line and the page ships the device chooser's client code (radix Tabs). It passes the required check but has little headroom: a noisy run can fail it.
7. **No ECC reviewer agents were run by this builder** (security/typescript/react/ponytail). Left to the lead's review pass.
