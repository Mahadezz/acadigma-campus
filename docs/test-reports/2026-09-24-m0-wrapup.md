## 1. Scope

**What this Part is.** Three independent gaps left over from M0's parallel build streams, closed together: (a) the two nav systems (`packages/domain/src/nav` and `packages/ui/src/primitives/nav-config.ts`) unified on domain's already-tested curated trees, and wired into the school shell (`apps/web/app/(school)/app`) for the first time — the shell previously read neither engine; (b) `supabase/tests/13_rls_grants_invariants.sql`, two whole-catalog invariants (every `public` table has RLS on, `anon` has no USAGE on schema `app`); (c) `supabase/tests/coverage.sql` + `scripts/check-coverage-test-files.mjs`, closing the "RLS coverage" CI step that has warned `coverage.sql` was missing since the workflow was written.

**Acceptance criteria covered:**

| AC-2 | The school shell picks its curated tree from `WorkspaceContext.role`, server-side              | `apps/web/e2e/journeys/school-shell-nav.spec.ts` (written; skipped in CI pending OQ-27, see §5)                 |

**Out of scope for this Part** (recorded in DECISION-LOG D-56):

- Full reconciliation of the nav's per-screen module keys and the plans engine's per-bundle `plan_modules` — only the 7 keys with a real equivalent are mapped; the rest stay ungated.
- Writing pgTAP coverage for the 5 pre-existing tenant tables `check-coverage-test-files.mjs` found with no test file at all (`consent_records`, `legal_acceptances`, `email_log`, `file_access_log`, `subscription_events`) — tracked in that script's `KNOWN_GAPS` allowlist, each attributed to the feature that should close it.

**Risk areas:**

- The module-key/plan-module mapping (`NAV_MODULE_TO_PLAN_MODULE`) silently defaulting an unmapped key to "always visible" rather than "always hidden" — tested explicitly (Pro-shaped and Starter-shaped plan fixtures in `entitlements.test.ts`).

## 4. Database (pgTAP)

**Ran for real in `CI / db` — [run 35998842703](https://github.com/Mahadezz/acadigma-campus/actions/runs/35998842703), job `db`, PASS.** (Could not run locally this session — no Docker.)

Getting here took two fixup commits after the first real CI run on this PR:

1. `13_rls_grants_invariants.sql`'s first assertion compared `array_agg(tablename order by tablename)` (`pg_tables.tablename` is type `name`) against `array[]::text[]`; pgTAP's `is()` has no `name[]` vs `text[]` overload and failed with `function is(name[], text[], unknown) does not exist`. Fixed by casting to `tablename::text`.
2. `pg_prove --ext .sql supabase/tests/*.sql` picked up `coverage.sql` too — it is plain SQL (no `select plan(N)`), so `pg_prove` failed it with "No plan found in TAP output". Fixed by excluding `coverage.sql` from that glob; it keeps running as its own separate `RLS coverage` step, as designed.

Both fixes are mechanical (a type cast, a glob exclusion) — neither changed what either file asserts. After both, every assertion passed on the first try:

| Table / invariant                        | Isolation assertions | Escalation assertions | Result   | File                                          |
| ---------------------------------------- | -------------------- | --------------------- | -------- | --------------------------------------------- |
