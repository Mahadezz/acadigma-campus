## 1. Scope

**What this Part is.** Three independent gaps left over from M0's parallel build streams, closed together: (a) the two nav systems (`packages/domain/src/nav` and `packages/ui/src/primitives/nav-config.ts`) unified on domain's already-tested curated trees, and wired into the school shell (`apps/web/app/(school)/app`) for the first time — the shell previously read neither engine; (b) `supabase/tests/13_rls_grants_invariants.sql`, two whole-catalog invariants (every `public` table has RLS on, `anon` has no USAGE on schema `app`); (c) `supabase/tests/coverage.sql` + `scripts/check-coverage-test-files.mjs`, closing the "RLS coverage" CI step that has warned `coverage.sql` was missing since the workflow was written.

**Acceptance criteria covered:**

| #    | Criterion                                                                                      | Covered by                                                                                                      |
| ---- | ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| AC-1 | `packages/domain/src/nav` is the single type/data source; `packages/ui` imports, not redefines | `packages/ui/src/primitives/nav-config.test.ts` ("this package's curated trees are the domain package's trees") |
| AC-2 | The school shell picks its curated tree from `WorkspaceContext.role`, server-side              | `apps/web/e2e/journeys/school-shell-nav.spec.ts` (CI-only, `E2E_LIVE_SUPABASE`)                                 |
| AC-3 | Bottom nav (phone) and sidebar (desktop) render the identical filtered tree                    | `packages/ui/src/primitives/bottom-nav.test.tsx`, `sidebar-from-config.test.tsx`; e2e journey, both viewports   |
| AC-4 | Module entitlement comes from the plans engine, never a guess                                  | `packages/domain/src/nav/entitlements.test.ts`                                                                  |
| AC-5 | Every `public` table has RLS enabled; `anon` has no USAGE on `app`                             | `supabase/tests/13_rls_grants_invariants.sql` (CI-only, pgTAP)                                                  |
| AC-6 | Every `workspace_id` table has RLS on and is named in a test file                              | `supabase/tests/coverage.sql` (CI-only) + `scripts/check-coverage-test-files.mjs` (run and passing locally)     |
| AC-7 | The dev-only `/design` page keeps working                                                      | `apps/web/e2e/design-smoke.spec.ts` (unchanged; not run locally — see §2/§5)                                    |

**Out of scope for this Part** (recorded in DECISION-LOG D-56):

- Full reconciliation of the nav's per-screen module keys and the plans engine's per-bundle `plan_modules` — only the 7 keys with a real equivalent are mapped; the rest stay ungated.
- Writing pgTAP coverage for the 5 pre-existing tenant tables `check-coverage-test-files.mjs` found with no test file at all (`consent_records`, `legal_acceptances`, `email_log`, `file_access_log`, `subscription_events`) — tracked in that script's `KNOWN_GAPS` allowlist, each attributed to the feature that should close it.
- The `/family` and `/personal` shells — those routes do not exist yet (M1/M2), so only `family:parent`/`personal:owner` curated trees exist as data; nothing renders them yet.
- Seller (`/sell`) and platform (`/platform`) nav — unchanged, still `packages/ui`-only, per DESIGN-SYSTEM §3.2 (entered from a link/the avatar menu, not resolved from workspace role).

**Risk areas:**

- The module-key/plan-module mapping (`NAV_MODULE_TO_PLAN_MODULE`) silently defaulting an unmapped key to "always visible" rather than "always hidden" — tested explicitly (Pro-shaped and Starter-shaped plan fixtures in `entitlements.test.ts`).
- Dropping `packages/ui`'s `ownerOnly`/`isOwner` gate in favour of `roles: ["owner"]` — verified the owner/admin split still holds via `nav-config.test.ts` and the rewritten `bottom-nav.test.tsx`/new `sidebar-from-config.test.tsx`.
- `coverage.sql`'s split across two CI jobs (a Postgres service container has no path to the repository checkout) — the split itself, and why `pg_read_file` cannot work here even as the superuser `PGUSER=postgres` connects as, is recorded in `coverage.sql`'s own header and D-56.
