## 1. Scope

**What this Part is.** An owner or admin can open `/app/settings/attendance`, see every field of the school's attendance policy (late/half-day counting, the late cutoff time, session mode, the minimum-attendance warning line, block-on-shortfall) with a plain-English line showing what a real student's attendance would be under the change — before saving anything — and save it. Teachers/staff already had the read-only summary at `/app/settings/overview` (Part 1); this Part gives owner/admin the editor. No migration: every dependency (`schoolAttendancePolicySchema`, `resolve()`'s defaults, the `updateSchoolSettings` write path) already existed from Part 1.

**Acceptance criteria covered** (spec §9, "Attendance" block, AC11/12/13/15 — the ones this Part's UI is responsible for; AC14 was already true from Part 1's `resolve()`):

| #       | Criterion                                                                                | Covered by                                                                                                                                                                       |
| ------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AC11/12 | Toggling `late_counts_present`/`half_day_counts_present` changes the computed percentage | `packages/domain/src/attendance/policy-preview.test.ts`, `attendance-policy-form.test.tsx`                                                                                       |
| AC13    | A policy change touches no stored `attendance_records` row                               | By construction: `getAttendancePolicySample` only reads (`select`); no write path in this Part. Not re-asserted by a row-hash pgTAP (that belongs to Part 1/F-AC-03, unchanged). |
| AC15    | The preview updates live as the form changes, before Save                                | `attendance-policy-form.test.tsx` — "shows the live effect line and updates it when a toggle changes, before any save"                                                           |

**Out of scope for this Part** — and where it is handled instead:

- Grade scale versioning, calendar (working days/timezone/periods), module visibility, ID patterns — separate Parts (D-212, spec §11 item 11).
- A dedicated `previewAttendancePolicy` server contract (spec §7) — deliberately not built; see D-212 and §11 item 11(b).

**Risk areas** — where the testing effort went:

- The sample-picking logic (`getAttendancePolicySample`): no session ever taken, a session with zero recorded days, and the register RPC itself failing all fold to the same "not enough data yet" empty result rather than an error, so a brand-new school's settings page never crashes.
- The live recompute matching the server-side `attendancePercentage()` exactly (same fixture, same function, imported not reimplemented) so the preview can never show a number the register wouldn't also show.

**Deliberately not tested, and why:**

- A dedicated server-side "preview" round trip: not built (D-212) — the preview is computed once server-side (the sample) and then purely client-side, so there is no server contract to integration-test beyond the sample fetch, which is unit-tested.

**Review round (2026-09-30, `security-reviewer` Opus, `typescript-reviewer`, `react-reviewer`, `engineering-database-optimizer`, `ponytail-review`) — fixed before merge:**

1. _MEDIUM (typescript-reviewer, react-reviewer, independently):_ the minimum-attendance % input was a controlled input whose displayed value came back from the rounded `min_attendance_bp`, so typing a decimal point (`72.`) or a trailing zero (`72.50`) was silently stripped on every keystroke. Fixed by keeping the raw typed string in its own state (`minInput`), mirroring `grade-scale-editor.tsx`'s `preview` field — the displayed value is never derived from the parsed/rounded number. New test: "the minimum-attendance field keeps a decimal point as it's typed, character by character."
2. _MEDIUM (typescript-reviewer):_ the effect line showed the raw `"2026-09"` fragment instead of a formatted month, undercutting the "plain-English" acceptance criterion. Fixed with a new `formatMonthYear()` in `apps/web/lib/format.ts` (mirrors the existing `formatDhakaDate`'s `Intl.DateTimeFormat`/`toIntlLocale` pattern), threaded through `page.tsx` → `AttendancePolicyForm`'s new `locale` prop. New test asserts `"2026-09"` never reaches the screen and `"September 2026"` does.
3. _LOW (typescript-reviewer):_ `AttendancePolicyEffect.eligible` was computed but never read. Surfaced as a warning line ("Below the {min} % minimum…") shown only when the draft policy's `after.eligible` is false, matching §5.6's "warning, never a hard block" semantics — nothing shown when the sample clears the minimum. New test covers both states.
4. _Reuse (ponytail-review):_ the client form redeclared its own `AttendancePolicySample` type, byte-for-byte identical to the one already exported by `packages/db/src/repositories/attendance-policy-preview.ts`. Now imports it instead of retyping it.
5. _Reuse, investigated and declined (ponytail-review):_ the same reviewer also flagged the form's local `fill()` template helper as a duplicate of `apps/web/app/(school)/app/attendance/format.ts`'s `fill`. On inspection, this codebase has a **documented existing convention** against a shared cross-route helper for exactly this function (`apps/web/app/(school)/app/home/format.ts:6-8`: "kept local to this route the same way that one is — no shared cross-route helper exists in this codebase yet"), and `grade-scale-editor.tsx` follows the same pattern with its own local copy. Matched the existing precedent instead — added the same documenting comment rather than introducing the first cross-route import of it.
6. _LOW, noted, not changed (security-reviewer):_ a bare `data as {...}` cast in `getAttendancePolicySample` (matches the established pattern elsewhere in this repository, e.g. `students.ts`/`basic-home.ts`) and a nondeterministic tie-break when two sections share the same latest date. The tie-break was fixed (a secondary `.order("section_id")` for a deterministic sample across page loads); the cast was left as-is, matching repo convention.
7. _Verified, no change needed (engineering-database-optimizer):_ the new `attendance_sessions` query is exactly the access pattern `attendance_sessions_workspace_date_idx (workspace_id, date)` was built for (equality + trailing-column ORDER BY + LIMIT 1); reusing `getAttendanceRegister` rather than a second SQL path was judged the correct tradeoff for an owner/admin-only, once-per-page-load call.

All five reviewers' post-fix state: unit tests re-run (13/13 new-file tests, up from 11 — the two new cases above), `pnpm typecheck`/`pnpm lint`/`pnpm format:check` clean.
