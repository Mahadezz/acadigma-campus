## 1. Scope

An owner or admin downloads a bilingual template, uploads a `.xlsx` or `.csv` register, sees a stored preview with every bad row (line, column, what is wrong in plain English or Bangla, what was typed), and imports the valid rows. Each row is admitted by `public.import_student_batch` through `public.admit_student`, so codes, roll numbers, guardians, enrolments, audit and every rule are the quick-admit ones. The report lives in `student_import_batches`, so a reload shows the same preview or result. Limits: 2,000 rows, 1 MB.

## 7. Security checks

Tenant context from `requireWorkspace`; `can("students.import")` then `requireWritable` in both actions; RLS owner/admin on the table; the function re-checks the role; no UPDATE/DELETE grant; every row re-validated by `admit_student`. `.xlsx` is read from a Buffer only (read-excel-file treats a string as a file path), after an `fflate` walk of the central directory refuses any entry declaring more than 10 MB unpacked or 20 MB in total; read-excel-file then parses only a re-zip of the allowed entries, each capped at its declared size. `pnpm audit --audit-level high`: no known vulnerabilities. Report data (DOB, phones) is redacted from the audit trail.
