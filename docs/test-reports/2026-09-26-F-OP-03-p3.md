## 1. Scope

**What this Part is.** A teacher, admin or owner can now generate a report card for a Class 6-ক student — real letterhead, subject rows with marks/letter/GPA, a totals line, an attendance summary with a below-minimum warning, and class-teacher/guardian signature lines, in Bengali or English — from `/app/reports`. Every letter and grade point comes from `@acadigma/domain`'s `bandFor`/`BD_GRADE_BANDS` (the #46/D-302 grade scale), never re-derived in `packages/pdf` (spec §5.1). Real exam/marks data (F-AC-06 marks entry) is not on `main` yet — this Part renders from a 40-student fixture behind one seam function (`getReportCardData`), documented in D-206.

**Acceptance criteria covered** (from spec §9; the report-card-specific ones):

| #    | Criterion                                                                 | Covered by                                                                      |
| ---- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| AC-5 | Letters/GPA/rank match the grade-scale function's output                  | `report-card-fixture.test.ts` (`bandFor`/`BD_GRADE_BANDS` reused directly)      |
| AC-6 | Changing the grade scale changes letters with no template change          | satisfied by construction — `packages/pdf` has no band table (§5.1)             |
| AC-7 | An F in any subject → GPA 0.00, result Fail                               | `report-card-fixture.test.ts` "a student with an F..."                          |
| AC-8 | A missing subject mark shows "—", card still renders, named as incomplete | `report-card.test.ts` "prints an em dash...", "names the incomplete subject..." |
| AC-9 | Attendance below minimum prints a warning line, still renders             | `report-card.test.ts` "prints the below-minimum attendance warning..."          |
| AC-1 | No hardcoded school name/logo (banned-strings)                            | `banned-strings.test.ts` (scans the whole package, including this template)     |
| AC-3 | `report_locale='bn'` → Bengali digits                                     | `report-card.test.ts` "prints Bengali digits for the roll number..."            |

**Out of scope for this Part** (spec §11 addendum items 14-17, decision D-206):

- Real marks data (`app.compute_exam_result`) — F-AC-06 Part 3 marks entry is not on `main`; the whole render path is fixture-backed behind the `getReportCardData` seam.
- Comments/AI, bulk report cards, publish-to-parent, attendance register, mark sheet, staff summary, profile sheet, ID cards — later Parts (4-8), not built.
- Signature-label customisation from `school_profiles.signature_labels` — locale-default text baked into the template.
- Row-scoping ("own sections") on `report.render.report_card` for a teacher — deferred, same cut Parts 1-2 already made for `report.render.sample` (no real section-teacher data to scope against while the render source is a fixture).

**Risk areas** — where the testing effort went:

- **The grade-scale/GPA rule must exactly match #46/D-302, not a re-derived copy.** Verified by importing `bandFor`/`BD_GRADE_BANDS` directly from `@acadigma/domain/grading` in the fixture (not copying the band table), and by a dedicated test that a fixture student with an F in any subject gets GPA 0.00 and `result: 'fail'` (§5.1's BD rule).
- **The seam's contract must hold under all three real cases** (known student+exam, unknown student, unknown exam) — `report-card-data.test.ts` — this is the boundary the real F-AC-06 query will sit behind, so its shape matters more than the fixture's own content.
- **Bengali glyph fidelity on the new template specifically** (not just the sample document) — a fresh golden test (`report-card.test.ts`) proving the student name, subject names and exam name survive font embedding, using the same character-multiset technique `golden.test.ts` established for the known ToUnicode round-trip limitation.
- Manual eye verification: rendered a Bengali and an English sample to `F:\tmp\ops-report-card\` and read the actual PDF pages (not just the extracted text layer) for both.

### Notable cases proven

- A student with an F in any subject gets GPA 0.00 and `result: 'fail'`, matching #46/D-302's BD rule exactly (no re-derived copy) — `report-card-fixture.test.ts`.
- A subject with no mark yet renders `null`/`—`, never a false `0`, and the card still renders with the student named in the incomplete-subjects banner — `report-card-fixture.test.ts`, `report-card.test.ts`.
- Rank is a real permutation of 1..40 across the fixture class, computed once over the whole class (GPA desc, total desc) — `report-card-fixture.test.ts`.
- The seam (`getReportCardData`) returns `not_found` for an unknown student, `not_found` for an unknown exam, and the correct DTO for a known pair — never throws — `report-card-data.test.ts`.
- `createReportRun` checks `report.render.report_card` (not `report.render.sample`) for a `report_card` request, and denies a role without it before touching the repository — `actions.test.ts`.
- A seam failure (`no_data`) marks the run `failed` and never calls `renderPdfToBuffer` — `actions.test.ts`.
- `GET /api/pdf/[runId]` re-parses the stored `params` with `reportCardParamsSchema` and 422s on a malformed stored params object rather than crashing — `route.test.ts`.
- Bengali student name, subject names ("বাংলা", "গণিত") and the exam name survive font embedding (character-multiset comparison, the established technique for pdfkit's known ToUnicode reordering limitation) — `report-card.test.ts`.
