## 1. Scope

**What this Part is.** An owner, admin or teacher can now print two new documents from real F-AC-03/F-AC-06 data: the **monthly attendance register** for one section (landscape A4, every calendar day of the month as a column, non-school days greyed, P/A/L/E/H codes, per-student totals and percentages, per-day present counts, the school's own late/half-day policy in a legend, and an "n days not yet taken" banner), and the **exam mark sheet** for one section x exam (landscape A4, students x papers, marks with Absent/Exempt shown, totals/GPA/grade/rank from F-AC-06's already-computed `results` — a student whose own result is incomplete or withheld still gets a row printing "অসম্পূর্ণ"/"Incomplete" instead of those fields). Two new `report_kind` values (`attendance_register`, `mark_sheet`) on the existing run pipeline — both single-item, synchronous renders, the same pattern every kind has used since D-205.

**Acceptance criteria covered** (from spec §9, the register/mark-sheet-specific ones; §9's register sign-off criteria 26a-26e are explicitly not covered — see "Out of scope"):

| #   | Criterion                                                                               | Covered by                                                                                                                                 |
| --- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 23  | A month with 26 sessions: per-student totals equal a direct count, legend states policy | `register-marksheet-perf.test.ts` (26-school-day October fixture) + manual pymupdf text-layer check; legend rendering verified visually    |
| 24  | A mark sheet with 14 subjects: landscape, no column clipped                             | Template always renders landscape (§5.7(4)); verified visually with 6 subjects (see §6) — 14 not separately tested, see Known issues       |
| 27  | A teacher who does not teach a section: `forbidden`                                     | Not enforced at this layer for the register yet (matches attendance's own existing row-scoping, D-105) — see D-208 item 7 and Known issues |
| 29  | A Free-plan workspace: `plan_required`                                                  | Reused unchanged from the existing `createReportRun` entitlement gate (`resolveEntitledNavModules`) — no new code path, not re-tested here |

**Out of scope for this Part** (task's own narrowing, recorded in D-208):

- **`attendance_register_signoffs`, the sign/countersign/reopen actions, the `PERIOD_LOCKED` write guard, and AC26a-26e** — the task named this deferral explicitly and D-208 explains why it is not "tiny."
- **Exam-subject-configured mark sheet column order** — inherited from `getSectionResults`'s existing alphabetical sort, not a new cut.
- **A repeated table header on a register that spans more than one landscape page** — the measured case (40 students x 31 days) is 2 pages; the header does not repeat on page 2 (see Known issues).

**Risk areas** — where the testing effort went:

- **Bengali digit rendering.** The first render attempt used a plain `<Text>` for several header/number cells instead of `ScriptText`, producing mojibake for every Bengali digit and label (Inter has no Bengali glyphs — `document-shell.tsx`'s own file header warns about exactly this). Found by rendering real PDFs and reading them with pymupdf, fixed by routing every dynamic string through `ScriptText`, then re-verified.
- **A narrower, real text-extraction defect found during that same verification**: a Bengali-locale value ending in exactly `.00` (two identical zero glyphs immediately after the isolated `.` run `ScriptText` splits out) loses its period in pymupdf/pdf-parse text extraction — visually unaffected (a normal decimal point prints), but the copy/paste-able text layer is wrong. This is pre-existing in the shared `document-shell.tsx`/`ScriptText` machinery (confirmed present for a `report_card`-kind PDF too, not something this Part introduced) and is documented as a known issue rather than fixed here (see §8).
- **No new SQL function for calendar data** — `getAttendanceRegister` reads `holidays`/`working_day_overrides`/`school_profiles.working_days` directly and recomputes `app.is_school_day`'s own override→weekly-pattern→holiday→true precedence in TypeScript; unit-tested against the same four cases that function's own migration comment names.
- **The mark sheet must never compute a grade, GPA or pass/fail itself** (§5.1's "one grading truth" rule) — `getMarkSheetData` only reshapes and does simple arithmetic (highest/lowest/average/pass-rate) over fields `getSectionResults` already computed.
