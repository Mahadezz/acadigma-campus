## 1. Scope

**What this Part is.** A teacher who opened her classes online can reload them with no signal: the page comes from the phone with "Last updated 09:12 today" and an offline banner. A page she never opened says "This needs internet the first time" with Retry instead of the browser's error. Report cards, PDFs, Publish, student import, Create school and guardian invitations read "Needs internet / ইন্টারনেট দরকার" while offline. The saved pages hold student data, so they are wiped on sign-out, on a workspace switch, and when the session, the membership or the role changes (checked on every app open and every return online).

### Notable cases proven (`decidePurge`)

- Nothing changed → keep; the server unreachable (network error / 503) → change nothing.
- Signed out or session revoked → purge and forget the snapshot.
- A different user, a different workspace, a changed role → purge.
- No active membership (removed or suspended) → purge, and keep purging while it lasts.
- No snapshot on record (a check that never got through, a session ended without `/login`, cleared storage) → purge (security review HIGH 1).

### Notable cases proven (browser side, fake Cache Storage)

- Sign-out wipes every `acadigma-data-*` cache and the snapshot, keeps the static caches.
- A workspace switch wipes even when `/api/offline/session` is unreachable, and keeps the old snapshot so the next check wipes again.
- Arriving at `/login` wipes with the session check failing; entering a shell from `/invite` re-runs the check.
- Every wipe asks the worker first (`acadigma-purge` message, sent while the data cache still exists); the check records the server clock offset from its `Date` header.
- `purge-guard`: a page write whose request began before a purge is refused; one already written when the purge ran is deleted; redirects and non-200s are never stored.
- `/api/offline/session`: `unauthenticated` → signed out; `dependency_unavailable` → 503 unknown; each other failure reason → signed in with no workspace; no user either → signed out.

## 7. Security checks

- The worker caches only full pages of `/app`, `/family`, `/personal`, only a plain 200 (never a redirect to `/login`); `/api/*` (signed file URLs, PDFs), RSC payloads, auth pages, `/account` and `/platform` are network-only. The old worker's generic caches (`pages`, `pages-rsc`, `apis`, `others`, …), which held exactly those responses with no purge, are deleted on activate.
- `GET /api/offline/session` returns only the caller's own user id, active workspace id and role (already shown in the shell), `Cache-Control: no-store`.
- The snapshot in `localStorage` holds ids only, never a token.
