## 1. Scope

**What this Part is.** A teacher who opened her classes online can reload them with no signal: the page comes from the phone with "Last updated 09:12 today" and an offline banner. A page she never opened says "This needs internet the first time" with Retry instead of the browser's error. Report cards, PDFs, Publish, student import and Create school read "Needs internet / ইন্টারনেট দরকার" while offline. The saved pages hold student data, so they are wiped on sign-out, on a workspace switch, and when the session, the membership or the role changes (checked on every app open and every return online).

**Acceptance criteria covered** (spec §9):

| #     | Criterion                                                                                     | Covered by                                                                                                        |
| ----- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| AC-1  | Opened page reloads offline with "Last updated"; unopened page shows "needs internet" + Retry | `e2e/journeys/offline-read-cache.spec.ts`                                                                         |
| AC-8  | After sign-out, Cache Storage has no `acadigma-data-*` cache (the IndexedDB half is Part 2a)  | `e2e/journeys/offline-read-cache.spec.ts`; `purge.test.ts` "purges and forgets on sign-out"                       |
| AC-9  | Membership removed / role changed → every data cache purged (the outbox half is Part 2a)      | `lib/offline/purge.test.ts` (removed, suspended, role changed); no e2e — see §8                                   |
| AC-10 | Offline, generate/send buttons read "Needs internet", disabled, nothing queued                | `e2e/journeys/offline-read-cache.spec.ts` (sample PDF button); `OnlineOnly` on the other six controls             |
| AC-17 | Switching school leaves no `acadigma-data-*` entries                                          | `lib/offline/purge.test.ts` "purges on a workspace switch"; the switcher runs the check before navigating; no e2e |

**Out of scope for this Part** — and where it is handled instead: the outbox, queued writes, the pending chip and the sign-out "unsent changes" question (Part 2a); conflicts and session-expiry resume (2b); marks (3); files (4); the 14-day lock, `storage.persist()` and the quota banner (5).

**Risk areas:** a cache that outlives the person who filled it (the purge); a cached redirect or login page served as a class page; Next's RSC payloads served from cache against the wrong router state (OQ-3); the worker growing on old Android.

### Notable cases proven (`decidePurge`)

- Nothing changed → keep; the server unreachable (network error / 503) → change nothing.
- Signed out or session revoked → purge and forget the snapshot.
- A different user, a different workspace, a changed role → purge.
- No active membership (removed or suspended) → purge, and keep purging while it lasts.
- First check after a sign-in (no snapshot; `/login`'s own check already wiped) → keep, remember the user.

The journey: sign in → open Reports and Classes online (both land in `acadigma-data-pages`, read from Cache Storage) → `context.setOffline(true)` → reload Classes: the heading, "Last updated HH:MM today" and the offline banner, axe clean → Reports: "Needs internet" disabled, no generate button, axe clean → Exams (never opened): "This needs internet the first time" + Retry, axe clean → online, sign out from the account menu → Cache Storage has no `acadigma-data-*` → offline, Classes shows the needs-internet page, not the roster.

Found and fixed by running it: the `/~offline` fallback page was never precached (app routes are not in serwist's manifest on their own), so an unopened page showed the browser's error — `additionalPrecacheEntries` in `next.config.ts` fixes it; and the first purge check after sign-in wiped the pages the user had just opened (the rule now keeps them, §3).

## 7. Security checks

- The worker caches only full pages of `/app`, `/family`, `/personal`, only a plain 200 (never a redirect to `/login`); `/api/*` (signed file URLs, PDFs), RSC payloads, auth pages, `/account` and `/platform` are network-only. The old worker's generic caches (`pages`, `pages-rsc`, `apis`, `others`, …), which held exactly those responses with no purge, are deleted on activate.
- `GET /api/offline/session` returns only the caller's own user id, active workspace id and role (already shown in the shell), `Cache-Control: no-store`.
- The snapshot in `localStorage` holds ids only, never a token.
