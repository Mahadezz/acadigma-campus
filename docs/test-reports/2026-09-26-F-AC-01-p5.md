## 7. Security checks

- Tenant context comes from `requireWorkspace`. The action runs `can("academics.section.write")` and then `requireWritable`.
- The function is SECURITY INVOKER, so RLS (T2) and the triggers decide. It also takes the workspace id, so a member of two schools cannot touch the other school's section.
- Composite FKs make cross-school rows impossible. Only owner/admin hold DELETE. Anon has no privilege and no execute. Audit rows are written by trigger. No new dependency.
