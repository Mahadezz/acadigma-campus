## 1. Scope

**What this Part is.** A teacher takes the roll with no signal: it is saved on the phone ("Saved on this phone · waiting to send", a "1 waiting" chip), survives a reload, and sends by itself — once — when the phone is back online. A correction made before it sends replaces it. A colleague's newer save comes back as a conflict, shown on the class screen and in the queue sheet, and is never overwritten. Nothing is sent as another account or into another school. Signing out with changes waiting asks first; a removed membership or another person's account deletes the waiting changes.

### Notable cases proven

- Replace-on-pending keeps the base version; a save made while one is **sending** becomes its own item and is sent next in the same run, rebased onto the version the first one returned.
- A save made while the send is failing is never lost (the lock is not held during a send — this was a real bug, found by the journey: the correction waited behind the replay's request and was lost on reload).
- Only the signed-in user's items for the active workspace are sent; another user's or another school's wait (and `queuedFor` is refused server-side under any other session).
- Classifier: success → removed; network error, `dependency_unavailable`, `internal`, `rate_limited`, `unauthenticated`, `WRONG_ACCOUNT` → wait; `CONFLICT` → Needs your choice; any other named refusal → Needs attention.
- Outbox purge: another user's database deleted; items for a workspace left deleted; a role change and a signed-out check keep them; no database is created for a user who has none.
- Real PostgREST, unchanged `save_attendance`: the same key twice → the stored result, one session, 3 records; a stale base → `CONFLICT`, the colleague's register stands; the same key with a different payload → refused, nothing written.

- One database per user; another user's is deleted on the next check; items for a workspace the user left are deleted; sign-out deletes every outbox after asking.
- The unconditional `/login` wipe still clears pages only (an expired session keeps its queue for the same user, §4.6).
