# Acadigma Campus — Product Decisions

**Purpose.** The Base44 prototype (`docs/reference/base44-inventory/`) contained ~95 ambiguities: features modelled twice, three role vocabularies, four grade scales, fake UIs over empty entities. This document resolves every one of them so the rebuild has a single answer per question. Each entry: **Q** (the ambiguity, with the inventory reference) → **Decision** → **Why**.

Owner-made decisions are marked **[owner]**; the rest were made by the engineering lead with rationale and can be overturned by the owner at any time — say so and the doc + code change together.

Owner-confirmed on 2026-09-17: stack (Next.js + Supabase + Vercel), web PWA first with Android/Windows wrappers, SSLCommerz BDT payments, brand **Acadigma Campus** (marketplace + hiring are modules inside it, not products), 30/70 commission, platform-staff moderation console, monthly payouts (min ৳1,000, 7-day hold), plan matrix with placeholder prices.

## 2. Academic core (inventory 02, Q1–Q16)

| #    | Q                                                            | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Why                                                                                                                            |
| ---- | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 2.1  | Attendance model (02-Q1, 02-Q12)                             | **Daily roll-call per section is the primary model**: `attendance_sessions` (section, date, optional period) + `attendance_records` (student, status ∈ present/absent/late/excused/half_day, note). Default status is `unmarked`; "সবাই উপস্থিত / Mark all present" ships as **one explicit header tap** writing an audited bulk action that records the actor's user id, surfaced in the monthly register — `defaulted_present` is dropped in favour of `bulk_marked_by` / `bulk_marked_at`, and the undo toast is retained (amended 2026-09-17 per SYNTHESIS row X-01). Gate/QR scan events (`attendance_scan_events`) are a **later input** that can pre-fill a session; the fake "live feed" is dropped. **Month-close lock**: the register carries class-teacher signature and head countersignature states; a closed month is not editable (amended 2026-09-17 per SYNTHESIS row X-03). | Every downstream feature assumed roll-call; scanning is hardware-dependent and belongs to the Windows/Android wrapper phase.   |
| 2.2  | Does late count as present? (02-Q2)                          | **Yes by default** (`late` and `half_day` count as present for %), configurable per school (`school_profiles.attendance_policy`). Minimum attendance for exam eligibility: configurable, default **75 %**, shown as a warning, not a hard block. The % denominator MUST be `app.is_school_day`, and long-holiday mode must not depress it (amended 2026-09-17 per SYNTHESIS row G-03).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | BD schools commonly use 75 %; making it a setting avoids re-arguing it.                                                        |
| 2.3  | Class = homeroom or class-subject? (02-Q3)                   | **Both, properly**: `grade_levels` (Class 1…12) → `sections` (Class 6 – A; the homeroom; has a class teacher) → `section_subjects` (section × subject × teacher). Students **enrol** in one section per academic year (`enrollments`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | This is the standard school model and the only one where "one student, one class" and "one teacher per subject" are both true. |
| 2.4  | Grade scale (02-Q4, 05-Q10)                                  | Per-school `grade_scales` with the **Bangladesh default**: A+ 80–100 → 5.00, A 70–79 → 4.00, A− 60–69 → 3.50, B 50–59 → 3.00, C 40–49 → 2.00, D 33–39 → 1.00, F 0–32 → 0.00. Subject %, letter and grade point per exam subject; **GPA = mean of subject grade points** (an F in any subject → GPA 0 per BD rule, configurable). Pass mark 33 (configurable). Class rank by GPA then total marks. Weighting across exams (e.g. 1st term 30 %, final 70 %) configurable per academic year.                                                                                                                                                                                                                                                                                                                                                                                                     | Four disagreeing scales was the worst parent-facing bug. One table, BD defaults, computed in one SQL function.                 |
| 2.5  | Work week (02-Q5)                                            | `school_profiles.working_days` default **Sat–Thu**, timezone **Asia/Dhaka**, `first_day_of_week` derived. Timetable and attendance UIs read this setting; no hardcoded 5-day weeks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | BD standard; the prototype had three contradictory answers.                                                                    |
| 2.6  | Sequential IDs (02-Q6, 03-Q10)                               | **Per-workspace sequential counters** (`id_counters` table, advisory-locked): `STU-2026-00001`, `ADM-2026-0001`, `WS-000214`. Pattern editable per school.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Random IDs collide; schools expect sequences.                                                                                  |
| 2.7  | Link exams ↔ marks, assignments ↔ marks (02-Q7)              | `exams` → `exam_subjects` (section_subject, date, max marks) → `marks` (student × exam_subject). Assignments have `assignment_submissions` (score, status). Report cards read exams only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Marks without an exam are meaningless for reporting.                                                                           |
| 2.8  | "Distribute a handout" (02-Q8)                               | Means: publish to section(s) → visible to those students' parents in the portal, optionally **push to print queue** with copies = enrolled count.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Both real outcomes; the boolean was a placeholder for them.                                                                    |
| 2.9  | Who takes staff attendance? (02-Q9)                          | Admin/owner mark others; every member can **self check-in** (geofence optional later). Teachers cannot edit others.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Matches the permission matrix, keeps self-service.                                                                             |
| 2.10 | Risk scoring: AI or formula? (02-Q10, 02-Q11)                | **Deterministic, explainable formula** (attendance %, mark trend, behaviour points, missing submissions; weights configurable) computed nightly by a DB job. AI is used only to _phrase_ a suggested intervention. A human-set flag is never auto-cleared.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Schools must be able to explain why a child is flagged.                                                                        |
| 2.11 | Student record: which of ~100 fields are mandatory? (02-Q13) | Admission wizard: **required** = name, DOB, gender, section, at least one guardian with phone. Everything else optional, saved as draft at any step. Health/ID documents are private files (see 6.5).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Blocking on 100 fields kills adoption; a draft state keeps data.                                                               |
| 2.12 | Drop `Grade` entity? (02-Q15)                                | Yes. Not migrated.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Zero references.                                                                                                               |
| 2.13 | Behaviour points scope (02-Q16)                              | **Per academic term**, with all-time view available. Parent-visible flag per log.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Leaderboards reset with terms in real schools.                                                                                 |

Teachers see their balance in the AI panel. (amended 2026-09-17 per SYNTHESIS row A-01, A-02, P-14). **Model routing is by language risk, not plan tier**: any Bangla, parent-facing output uses the stronger model on every plan; cost is controlled by _which actions_ a tier may call, never by degrading Bangla (amended 2026-09-17 per SYNTHESIS row A-04). | The prototype gave unlimited free LLM use with a fake meter.
