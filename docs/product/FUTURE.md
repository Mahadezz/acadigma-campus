# Acadigma Campus — Future scope (explicitly not in v1)

Items here were seen in the Base44 prototype or raised during planning and deliberately deferred. Each has a note on what would trigger it and what v1 already prepares.

| Item                                                                            | Why deferred                                               | v1 preparation                                                                                                                   | Trigger to build                              |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| **Acadigma Students app** (student accounts, homework submission, self-service) | Separate app in the suite (owner decision D-10)            | Students are records with stable ids; `enrollments`, `assignments`, `assignment_submissions` designed for a future student actor | Campus R1 live in ≥ 5 schools                 |
| **Acadigma Parents app**                                                        | Separate app; Campus keeps the read-only parent portal     | `guardian_users` linking, parent RLS policies, notification events                                                               | Parent portal usage data                      |
| **Acadigma Admin (finance) app**                                                | Separate app pulling Campus data                           | Money in paisa, invoices, expense ledger, audit                                                                                  | After R3                                      |
| **Stripe / international cards**                                                | Bangladesh-first; SSLCommerz covers local rails            | `PaymentProvider` interface                                                                                                      | First international school or seller          |
| **SMS / WhatsApp Business provider**                                            | Cost + provider onboarding                                 | `contact_log`, announcement model, notification channels enum includes `sms`                                                     | Owner picks a provider (SSL Wireless, Twilio) |
| **Gate / QR scan attendance hardware & camera scanning**                        | Needs native camera; hardware varies                       | `attendance_scan_events` table + QR on ID cards                                                                                  | Android wrapper (R4)                          |
| **Local print agent (Windows)**                                                 | Native OS access                                           | `print_jobs`, `printers` tables, agent protocol doc                                                                              | Tauri app (R4)                                |
| **Offline-first attendance by default**                                         | PWA background sync limits on iOS/Android WebView          | Idempotent attendance save, IndexedDB queue                                                                                      | Android wrapper (R4)                          |
| **Multi-campus organisations**                                                  | One workspace = one campus keeps RLS simple                | `workspaces.parent_workspace_id` reserved (nullable, unused)                                                                     | A school group signs                          |
| **Google / Microsoft SSO**                                                      | Supabase supports it; not needed for BD schools yet        | Auth provider abstraction in Supabase                                                                                            | Enterprise plan customer                      |
| **MCP / OAuth surface for AI clients** (prototype `OAuthConsent.jsx`)           | No demand; security surface                                | —                                                                                                                                | Explicit owner request                        |
| **Per-seller / per-category commission**                                        | Single 30 % rate chosen                                    | Rate snapshotted per order line, so a per-seller rate is a column away                                                           | Marketplace scale                             |
| **Fee management / tuition invoicing to parents**                               | Belongs to Admin (finance) app                             | Money model, invoices                                                                                                            | Admin app                                     |
| **Library (physical books) circulation**                                        | Prototype `SchoolBook` was a reading list, not circulation | `resources` cover digital books                                                                                                  | Owner request                                 |
| **Transport / hostel modules**                                                  | Not in prototype                                           | —                                                                                                                                | Owner request                                 |
| **AI proctoring, essay grading**                                                | Ethics/accuracy risk                                       | AI adapter + credits                                                                                                             | Owner request with policy                     |
| **Integrations directory (23 fake connectors in prototype)**                    | None were real                                             | Real integrations: email, SSLCommerz, Claude, ICS                                                                                | Specific customer need per integration        |
