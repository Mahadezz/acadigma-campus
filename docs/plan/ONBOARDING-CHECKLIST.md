# Onboarding checklist — the owner's first week at a school

For the owner (or whoever visits), when a school agrees to try Acadigma Campus. Short, plain English, printable. D-72 records why this exists: the messy realities of a real school surface fastest in person, and they belong in an issue, not lost after the visit.

---

## Before the visit — ask for

- Their student register, in whatever file they already have it (Excel, CSV, even a photo of a printed list if that's all there is).
- Their class and section list (which grades, how many sections each, section names).
- Their teacher list (names, which classes/subjects each one covers, phone numbers for invites).
- Their grading rules, if they have a written one (pass marks, grade bands, how they compute GPA) — otherwise the BD default bands are used.

## Day 1 — on site

1. **Create the school.** Name, address, logo if they have one, academic year.
2. **Set up classes and sections.** Match what they told you before the visit; add rooms and class teachers if known.
3. **Import the register.** Use the import screen's preview step before committing — walk through it with them so they see what will be created, and catch anything that looks wrong (a merged cell, a duplicate ID) before it becomes 40 student records to fix by hand.
4. **Invite the teachers.** One invite per teacher, to the phone/email they gave you. Confirm at least one can sign in on their own phone before you leave the room.
5. **Turn on Basic mode and set text size** for any teacher who is older or less comfortable with apps — ask, don't assume. Large or XL text, Basic mode's simpler class-by-class layout.

## Days 2-5 — while they get used to it

- **One real roll call**, done by an actual teacher, for one actual class, on a normal school day. Watch them do it once; don't do it for them.
- **One test's marks entered**, for one subject, by the teacher who owns that subject.
- **One report card printed**, for one student, and put it in front of the school so they see the real output, not a screenshot.
- **Collect what broke.** A screen that confused someone, a word they didn't understand, a step that took too long, a file format the import didn't like. Write it down as it happens, not from memory later.

## After the visit

- **Log every messy file format you saw** (a register with merged header rows, mixed English/Bangla names in one column, a class list as a photo, phone numbers in three different formats) as an issue against the import feature. This is what actually makes the importer better for the next school, not a spec written from imagination.
- File any other rough edges from the "collect what broke" list as their own issues, one each, with enough detail that someone who wasn't there can act on it.
